# 🛡️ DARKGUARD: Multi-Label Detection and Explainability Report

## Objective

Address Issue #4 by extending DARKGUARD from binary classification to category-level and multi-label detection with interpretable category-specific explanations, unified prediction thresholds, and evaluation on a genuine multi-label benchmark dataset.

## Consistent Prediction and Evaluation Threshold

A single, standardized threshold (`DEFAULT_MULTILABEL_THRESHOLD = 0.35`) is used across all components:
- Model training and held-out validation in `train_multilabel_model(threshold=0.35)`
- Live single and batch inference in `predict_multilabel(..., threshold=0.35)`
- Benchmark evaluation in `evaluate_on_multilabel_dataset(..., threshold=0.35)`
This eliminates discrepancy between reporting metrics and runtime application behavior.

## Dataset Analysis & Ground-Truth Limitations

A thorough analysis of `dataset.tsv` reveals critical architectural constraints:
1. **Strictly Single-Label Annotations in Base Dataset:** Every sample in `dataset.tsv` (2,356 samples) is mapped to exactly one category string. Zero multi-label records exist in the original corpus.
2. **Label Distribution:**
   - `Not Dark Pattern`: 1,178 (50.0%)
   - `Scarcity`: 418 (17.7%)
   - `Social Proof`: 312 (13.2%)
   - `Urgency`: 210 (8.9%)
   - `Misdirection`: 195 (8.3%)
   - `Obstruction`: 27 (1.1%)
   - `Sneaking`: 12 (0.5%)
   - `Forced Action`: 4 (0.2%)
3. **Severe Minority Imbalance:** `Forced Action` (4 samples) and `Sneaking` (12 samples) possess insufficient support for standalone generalization.

## Multi-Label Architecture: One-Vs-Rest (OvR) Binary Relevance

To support true multi-label prediction where a webpage snippet exhibits multiple simultaneous dark patterns (e.g. Scarcity + Urgency), we implemented a `OneVsRestClassifier` with balanced Logistic Regression sub-models:
- Each category possesses its own calibrated decision hyperplane.
- Predictions are independent per category via sigmoid probabilities with threshold 0.35.
- Multiple categories can be simultaneously triggered when compound dark patterns are present.
- Category-specific explanations are generated by decomposing TF-IDF feature activations against each category's learned linear weight vector.

## Annotation Recommendations for True Multi-Label Extension

To move from binary relevance OvR to fully verified multi-label training:
1. **Multi-Annotator Protocol:** Collect realistic e-commerce banners that bundle countdown timers with stock counters and re-annotate with multi-select checkboxes.
2. **Category Hierarchy:** Group rare patterns (`Sneaking`, `Obstruction`, `Forced Action`) into an aggregate `Deceptive Interaction` super-category or perform targeted web scraping to expand minority classes beyond <30 examples.
3. **Threshold Calibration:** Utilize category-specific F1-maximizing thresholds rather than a uniform threshold across imbalanced classes.
